Understanding Meta's agentic recommendation system for Connected TV—an industry-oriented architecture that uses LLM agents to reason over trends, events, location, time, and cross-surface activity; MediaBrain to retrieve videos through Semantic IDs; traditional ML models for precise ranking; and asynchronous caching to keep LLM inference off the critical path.

Paper: An LLM-powered Agentic Recommendation System for Connected TV Content Discovery (Shi et al., Meta, July 2026)

TL;DR#

The system generates a personalized CTV homepage as multiple topic-based channels rather than one ranked feed. Its pipeline has three stages:

  1. Topic retrieval agent: a Llama-3 70B model turns a natural-language user/context snapshot into timely topic names.
  2. Media retrieval and ranking agent: a 1B-parameter generative retrieval model called MediaBrain maps each topic to Semantic IDs and retrieves candidate videos; conventional ranking models then personalize the videos inside each topic.
  3. Topic ranking agent: an LLM orders the completed topic channels using context, historical topic engagement, freshness, diversity, and media-quality indicators.

The most important engineering decision is that none of this LLM inference sits on the user-facing critical path. The page reads precomputed results from a cache; the agentic pipeline runs asynchronously afterward and refreshes the cache for later requests. MediaBrain is further accelerated through component-level caching, cursor-carried generated tokens, and vLLM optimizations. The reported throughput rises from 2 to 200 QPS per A100, a 100× improvement.

Why CTV Recommendation Is Different#

A mobile feed usually asks for one total ordering of items. A CTV homepage instead contains several horizontal carousels, each expected to be internally coherent while the page as a whole covers diverse interests.

The viewing mode is also different. Television is a “lean-back” experience: users expect something closer to a timely programming guide. Breaking news, sports finals, cultural events, seasonal moments, location, and time of day therefore matter more than they often do in a history-dominated mobile feed.

Traditional recommenders can use these signals, but every new signal type generally requires a schema, feature pipeline, model integration, and tuned heuristics. The paper’s alternative is to serialize heterogeneous inputs into natural-language statements and let LLMs reason over them directly.

Architecture Explained#

The LLMs reason at the topic level; specialized recommendation models still perform latency-sensitive media ranking. (Diagram created for this blog, based on Figure 1 and Sections 3.1–3.4 of the paper.)

A single orchestration layer owns context construction and the contracts between agents. Each component can be enabled, disabled, or experimentally replaced independently. Outputs at every boundary are saved to structured logs, creating a provenance trail for debugging and offline evaluation.

Step 0 — Construct a Shared Natural-Language Context#

The orchestrator combines structured, semi-structured, and unstructured signals into one prompt-friendly snapshot. Examples include:

  • date and time of day;
  • long-term interests;
  • recent searches and interactions;
  • topics watched, dismissed, highly engaged with, or frequently skipped;
  • location;
  • active trending or seasonal events.

For event awareness, the system uses a curated feed containing each event’s name, description, geography, and active date window. Active events are inserted directly into prompts. Adding a new source therefore needs a feed extension rather than model retraining or a new feature transformation.

Step 1 — Generate Topic Channels#

The topic retrieval agent is one instruction-tuned Llama-3 70B inference call. It receives seed interests and the shared context, then returns short, specific topic labels such as “NBA Playoffs Highlights” or “Hidden Tokyo Alleyways.” The prompt explicitly requests diversity, timeliness, specificity, and avoidance of topics already watched in the session.

Before downstream use, generated topics pass through two safety controls:

  • a curated sensitive-topic blocklist;
  • an asynchronous high-risk-content classifier.

Step 2 — Retrieve and Rank Media#

Each generated topic is dispatched in parallel to the media recommendation stack. This is deliberately hybrid:

  • MediaBrain handles open-ended natural-language retrieval;
  • early- and late-stage ranking models optimize behavioral objectives such as predicted watch time, likes, and shares;
  • existing integrity checks, freshness gates, inventory constraints, and other retrieval sources remain in the loop.

This division avoids asking an LLM to perform media-level personalization where specialized ranking models are still more accurate and scalable.

MediaBrain: Generative Retrieval with Semantic IDs#

MediaBrain maps a topic prompt directly to video candidates represented by Semantic IDs (SIDs).

  1. Media embeddings are quantized using Residual-Quantization k-means.
  2. Every video receives a four-level SID; each level has a codebook size of 1,024.
  3. Earlier tokens represent broader concepts, while later tokens capture finer distinctions.
  4. A Llama 3.2 1B model has its vocabulary expanded with SID tokens.
  5. The model is supervised-fine-tuned on several topic/media alignment tasks.
  6. At inference time, beam search generates SID sequences.
  7. Prefix lookup maps those generated SID prefixes to indexed videos.

The training tasks include topic→SID, SID→topic, keyword→SID, activity→SID, location→SID, celebrity→SID, category→SID, and search-query→SID. This diversity matters because the model must connect open-ended language to the media catalog rather than memorize one query pattern.

Step 3 — Rank Complete Topics#

The final agent receives:

  • the shared context;
  • historical topic-level engagement;
  • each topic’s ranked media slate and quality indicators.

It then orders the carousels to balance affinity, diversity, freshness, and timeliness. Importantly, this is topic-level ranking—not replacement of the media-level behavioral ranker.

Production Engineering#

The critical production pattern: serve cached recommendations first, then perform expensive generation asynchronously. (Diagram created for this blog, based on Sections 3.7 and 4.1 of the paper.)

1. Move LLMs Off the Critical Path#

A CTV homepage must appear within hundreds of milliseconds, while MediaBrain alone ordinarily needs about 500 ms for token generation plus 150 ms for prefix lookup. The system therefore serves cached output immediately and launches asynchronous computation after the response. Later requests consume the refreshed inventory.

2. Cache Components Independently#

Different inputs evolve at different speeds. Long-term interests can be cached aggressively, while in-session activity should remain fresh. The system gives each component its own cache lifetime and reruns only stages whose inputs materially changed.

MediaBrain also separates:

  • the cache for generated SID tokens;
  • the prefix-lookup cache, keyed by tokens plus scoring parameters.

This allows the same generated tokens to produce different candidate sets under different retrieval configurations without another LLM call.

3. Carry Generated Tokens in the Cursor#

For chained pages, generated SID tokens are serialized into the response cursor and sent back by the client on the next request. The server can skip generation and proceed directly to prefix lookup.

This is effectively session-scoped memoization without maintaining a server-side per-session token cache. The cursor naturally limits the cached value’s lifetime to the browsing chain.

4. Remove Serving Bottlenecks#

Beam search over four-token SIDs expands into roughly 150 vLLM decoding calls per query. The paper reports this optimization sequence:

Serving configuration Throughput per A100
Naive vLLM setup 2 QPS
Concurrent request handling ~40 QPS
Remove repeated prompt tokenization and sampling-parameter copies 80 QPS
Distribute beam-search orchestration across multiple model instances 200 QPS

The last step raises GPU utilization by approximately 4×. Overall throughput improves by 100×.

Evaluation and Results#

The paper does not report a full online A/B test for the complete three-agent CTV system. Its quantitative evaluation focuses on MediaBrain retrieval relevance and serving performance.

An LLM judge labels retrieved media as topically relevant or irrelevant across:

  • CTV100: the 100 highest-impression topics;
  • CTV1000: the 1,000 highest-impression topics;
  • Niche Entities: 150 manually curated cities, celebrities, and brands.

The central result is not simply “more data wins.” A 1.7-billion-example baseline trained for 74 hours is substantially improved by smaller, cleaner, evaluation-aligned datasets. The authors identify training-data quality and task diversity as the most important modeling factors.

Prompt-Time Adaptability#

The model can alter retrieval behavior through richer prompts without retraining. A generic “Interior Design with LED lighting” query over-focuses on LED signs and neon installations. Adding intent such as “a pleasing living environment with modern minimalist wooden aesthetics” shifts retrieval toward warm, wood-accented spaces. Adding platform context produces more visually curated and product-oriented media.

This is the main practical benefit of the LLM backbone: upstream agents can inject new context and stylistic intent directly into the retrieval prompt.

Limitations and Future Work#

The Pipeline Is Not Yet Closed-Loop#

The current architecture is unidirectional. If a generated topic has poor inventory or low media relevance, that failure does not teach the topic agent to avoid similar topics. If users repeatedly skip a topic category, the signal does not automatically feed back into future topic generation.

The authors propose a cross-session memory layer containing structured downstream outcomes—coverage, relevance, and engagement—that the orchestrator could insert into future prompts.

Semantic IDs Lose Fine-Grained Entity Information#

Niche-entity relevance saturates even after additional training. The authors measure how concentrated a topic is across first-level SID clusters using the Herfindahl–Hirschman Index (HHI). Across 902 topics, SID concentration and relevance have a Spearman correlation of 0.25.

Broad topics such as basketball map to concentrated SID regions more cleanly than entities such as Hello Kitty, brands, cities, or celebrities. This suggests that either the source media embeddings or the quantization step discards distinctions needed for fine-grained retrieval.

End-to-End Product Impact Is Still Unproven Here#

The paper gives convincing serving measurements and MediaBrain relevance results, but it does not isolate the online contribution of:

  • LLM topic generation;
  • LLM topic ranking;
  • the full hybrid pipeline;
  • cache staleness versus contextual freshness;
  • safety-filter precision and recall.

Those are the most important missing measurements for judging the complete system rather than one retrieval component.

My Thoughts#

Advantages and Lessons#

1. “Agentic” Means Routing, Not Replacing Everything with an LLM#

The strongest idea is architectural restraint. The LLM performs semantic reasoning and open-ended generation; conventional recommenders retain media-level personalization, integrity enforcement, and latency-sensitive ranking. This is a more credible production pattern than an end-to-end LLM recommender.

2. Natural Language Becomes an Integration Layer#

The context object acts like a flexible interface between heterogeneous data sources and reasoning components. New signals can be serialized into language and introduced via prompt changes. This can shorten experimentation cycles, though mature deployments will still need governance, validation, and observability around that supposedly “schema-free” interface.

3. The Most Reusable Contribution Is the Serving Design#

Asynchronous refresh, independent cache lifetimes, caching generated tokens separately from lookups, and carrying model output in a pagination cursor are broadly useful patterns for putting expensive generative components behind interactive products.

4. Better Data Beats Brute-Force Scale#

The MediaBrain experiments show that evaluation-aligned tasks, clean examples, and balanced entity coverage outperform a much larger but less targeted dataset. For generative retrieval, the quality of the language-to-item-ID bridge is more important than raw example count.

5. Semantic IDs Are Both the Enabler and the Bottleneck#

SIDs make autoregressive retrieval possible, but their hierarchy determines what the model can distinguish. If an entity is scattered across clusters—or semantically collapsed during embedding or quantization—additional LLM training cannot fully recover the missing catalog structure.

Big Picture#

This paper presents a practical blueprint for agentic recommendation: let LLMs convert messy real-world context into structured decisions, retain specialized ML where precision and throughput dominate, and hide expensive inference behind asynchronous computation and carefully designed caches.

Its clearest achievement is engineering feasibility rather than proof that every agent improves user outcomes. The next decisive evidence would be end-to-end online experiments showing that context-driven topic generation and topic ranking add measurable value beyond MediaBrain and the existing recommendation stack.
